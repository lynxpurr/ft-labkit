# 微调方法论手册

> 提炼自若干真实的微调项目。本件携带**纪律与方法论骨架**；
> 具体结论（超参、配比、阈值）留在各项目仓，勿在此预设。

## 1. Spec-coding 映射（业界实践 ↔ labkit 治理）

业界 spec-driven development（spec-kit 一系：constitution → specify → plan → tasks →
analyze → implement）面向**软件构建**；微调实验项目在其上多一层**实验规格**——
判决规则必须在实验前写死。映射如下：

| spec-kit 阶段 | 业界做法 | labkit 映射 |
|---|---|---|
| constitution | 项目原则/不可妥协约束，先于一切 | 项目 charter（CONSTITUTION.md：任务定义/边界与停止条件/Gate） |
| specify | 写 what/why，spec 为事实源 | PLAN.md 波次条目 + **预注册 R#**（量化判据 + 双向枚举） |
| plan | 技术方案 how | 波次"动作形态"段 + HANDOFF.md §2 当前阶段 |
| tasks | 小而可验证的任务 | T-N 任务清单，每任务带 REQ-N 验收判据（specs/spec-template.md） |
| analyze | 一致性校验 | 机器可查门：评测器自检 / 模板对拍 / 泄漏检查 / 参数快照核对 |
| implement | 按任务执行 | 带门的 run 脚本 + 证据只增不改 + reports/ |

预注册 R# 格式（写死才许跑）：

```
- 预注册：**R#** <主判据：量化判据 + 测量口径> + 护栏（<不回退轴及阈值>）
  - 过 → <下一步>
  - 不过 → <下一步（含诚实停止分支）>
- 判决落表（跑后回填）：中/不中 + 读数 + 指针
```

## 2. 项目骨架：测量先行，杠杆穷举，收官判据前置

1. **评测器先行**：新项目第一件写的不是训练脚本，是评测器 + 自检门。
   金标过不了自检 = 评测器有 bug，禁跑模型。
2. **零训练基线矩阵**先跑：容量阶梯（零训练测量）定"门槛在哪、哪些轴 0 起点、
   哪些行为不用教"。零样本已会的轴不要花数据预算。
3. **四杠杆 × 失败轴**实验框架：杠杆 = 容量 / LoRA 秩×缩放 / 数据构成 / 偏好优化；
   失败轴按项目自定义（如数值正确性、缺省值处理、取值子类型、澄清行为）。
   同一改动读数按轴分裂，**单配方全优是伪目标**。
4. **收官判据前置**：立项时预注册"什么时候停"（信号残量/杠杆完成度/边际收益），
   与"做什么"同等重要。

## 3. 判读纪律

- **读数分侧分轴报**：裸模型读数 vs 系统带件读数分开；失败轴分列。
- **中间值是稀释的签名**：组合配方读数落在两单轴之间 → 互相稀释非兼得。
- **逐位全等指纹有适用条件**：多容量同错逐位全等证明的是"同一副低秩眼镜读同一页
  教材"，不是数据上限。
- **失败归因有保质期**：开工前用最新评测列做逐条失败形态 diff；审计推翻立项假设
  是常态（每个项目都发生过两三次）。
- **同型预判错第二次出现，升设计层默认反转**（低估"显式契约+示例"的零样本能力
  是最常见同型错判）。

## 4. 训练配方基线（锚点，非结论）

- SFT/QLoRA：LoRA r16/α32（**α/r 恒定**，rank 对照必须保缩放）、全部投影层挂、
  lr 2e-4 cosine、3 epoch、有效 batch 16、思考模式按任务关闭。
- DPO：lr 5e-6 量级（SFT 的约 1/40）、β 不敏感先扫步数、参考模型复用 SFT 适配器
  （显存不翻倍）、最小有效剂量起步（数步级）。
- 序列长度、步数、显存需求**实测不估算**：tokenizer 定 max_length、截断探针定
  cap、GPU 预检门用实测峰值+余量。
- 模板对拍通过才开训（官方模板 vs 训练框架实效编码，带损失掩码的实效口径）。
- 剂量学：1 步无效 → 数步咬合饱和 → 更多步过校正；饱和即停。

## 5. OOD 三层分解（读数归因框架）

分布内满分 ≠ OOD 就绪。OOD 缺口三层正交，归因必须分列：

| 层 | 症状 | 治法 | 归属 |
|---|---|---|---|
| 形态学层 | 缺节/拼写/字段错位 | schema 自修外挂 | 部署侧，零训练，ROI 最高 |
| 数值捷径层 | 表述形态×单位联合空白 | 对症数据（覆盖计数粒度=字段×单位×形态） | 训练侧 |
| 行为边界层 | 误追问/编造判别 | DPO（行为收益开关型） | 偏好侧 |

## 6. 叠加分界律

- **管线式叠加合法**：SFT→DPO（adapters 模式）零契约风险。
- **同目标加数据回底座重演**，不要在冠军上续训 SFT（出口词漂移/断崖放大）。
- 终态 = 主配方 + 分轴组件 + 组装查询表，不是单体 checkpoint。

## 7. 数据纪律

- 增强只源自 train 内部，评测集一字不入；sha256 + PROVENANCE 锚定。
- 防泄漏：同族不跨集 / 跨集重复样本去重 / 合成×外部零重叠，各配植入泄漏的
  阴性对照测试。
- 确定性造数：零 RNG、稳定排序、配额断言、生成后用判分器复检回比。
- DPO 对：偏好信号只放目标链（两侧同输入）；负例可复用失败实验产物；
  核对"空思考块落在公共前缀"，别让偏好信号被思考差异污染。

## 8. 工程护栏（已固化为 labkit 件，此处存 WHY）

| 件 | 由来（教训的形状） |
|---|---|
| GPU 预检门（NEED=实测峰值+余量） | 共享卡上多次 OOM 之后才定下分波型需求线；余量给少了只差几十 MiB 也会在首步 OOM |
| 幂等=末步 ckpt 存在 | 失败残留目录曾被误判完成、静默吞掉整条实验臂 |
| ckpt 选择器按数字比较 + 选中即校验 | 按分隔符排序被路径里的连字符污染，checkpoint-73 静默当选 |
| 证据只增不改 + 按 generated 取最新 | 字典序覆盖坑（`-`<`.` 旧文件覆盖新键） |
| 报错 fallback 链不可信 | 校验器的 fallback 曾置换掉真实诊断 |
| 文本判断用退出码不用子串 | "validation failed" 含 "valid" |
