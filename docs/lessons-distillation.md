# Lessons 晋升管道约定

> 教训不能只躺在 notes/lessons.md 里。本件定义四级晋升管道与触发规则，
> `labkit close` 在每个波次收尾时检查其中的"批次"与"晋升记录"两项。

## 1. 四级管道

```
L1  notes/lessons.md        追加批制（## YYYY-MM-DD · XX批（主题）），按"形状"归档不按波次
        ↓ 蒸馏（同型第二次出现必晋升，不可再拖）
L2  notes/playbook.md       操作级规则（一条 = 触发条件 + 动作 + 出处指针）
        ↓ 泛化（确认跨项目可携带时）
L3  skills/*/SKILL.md       跨项目携带的操作层知识（查重后并入）
        ↓ 机械化（可机器执行时，最高形态）
L4  labkit/*.py             护栏代码：GPU 预检门即从教训变代码的实例
```

反向禁止：跳级沉淀（新教训直接写进 skill 或代码）须先在 lessons.md 落账——
没有出处账目的知识不可晋升。

## 2. 触发规则

- **同型教训第二次出现 → 必须至少晋升一级**。"同型"按形状判（现象的结构相似），
  不按表面文字判。
- **波次收尾必查**：`labkit close` 要求当日 lessons 批次带"晋升记录"行。
  与既有 playbook/skill 的重叠度扫描、晋升候选清单，由人或 agent 逐条决策并记录理由。
- **负向教训也沉淀**：预注册错判是资产。错判台账按形状归档，同型错判第二次
  出现即升设计层默认反转（docs/methodology.md §3）。

## 3. Dedupe-check（晋升前必做）

并入 L3/L4 前查全部已有落点，按优先级处理：

1. 已有精确对口 → 引用不重复
2. 部分覆盖 → patch 增量
3. 既有 class-level 条目下加 references 子页
4. 确无覆盖 → 新建（命名禁止一次性会话产物名）

## 4. 不沉淀清单

以下类型只进 lessons 账目，不晋升：

- 环境依赖性故障（换机器即失效）
- 工具负面断言（版本升级可能翻转）
- 重试即过的瞬态错误
- 未经阴性对照验证的单一观察

## 5. 版本与回溯

- 每次晋升在 lessons.md 批次尾部落"晋升记录"行：`→ L2 playbook §x` / `→ L4 gpu.py`
- L4 化的教训，其 labkit 件的单测须包含"该教训的阴性对照"（例：幂等判据的单测
  必须包含"目录存在但末步 ckpt 缺失"的用例）
