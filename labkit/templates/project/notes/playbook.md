# Playbook（操作级方法论）

> 从 lessons 蒸馏出的可执行规则：一条 = 触发条件 + 动作 + 出处指针。
> 项目级规则写这里；跨项目规则晋升到 labkit 仓（docs/lessons.md）。

## §1 开工序与判决纪律

- 规则：新 session 按 HANDOFF §1 五步开工检查走，跳步=停。

## §2 训练工程

- 规则：max_length/步数/显存需求实测不估算；NEED=实测峰值+余量。

## §3 评测

- 规则：评测器与自检门先行；判分口径改动必须重过自检门+阴性对照。
- 规则：等价验证用锚带判据（同数据同流程历史读数 ±容差落带），不设绝对
  阈值；带外先配方要素 diff；参数快照对锚逐项 diff 不等带外也做（diff
  即缺陷探测器）；单点等价后可按列/变体扩证。
- 规则：外部判分依赖（求解器快照/venv）在 data/PROVENANCE 钉版本——重钉
  必重跑锚带。

## §4 检查与 GPU 操作律

- 规则：存在性/匹配检查防自匹配（pgrep 模式拼串、正则锚语义位，检查者自身
  不得命中判据）；进程名匹配用 `xxx[.]yyy` 方括号形态，`pkill -f` 禁用与
  自身命令行同串的模式——方括号只护模式串，
  **整条命令行（含 echo/日志文案）禁明文目标串**；排查类扫描排除整条祖先链与包装
  进程，能按进程名匹配就不匹配完整命令行。
- 规则：重载训练起跑前卸载可卸第三方，比等窗口可靠——轮换型第三方会中途
  上卡触顶。
- 规则：验收谓词锚定被验对象本身（进程表而非绝对 free；无活监听而非无 TCP
  残留）。
- 规则：载具/环境检查的"绿"= 真命令冒烟通过（rc==0），存在性+可执行位会假绿。
- 规则：起外部推理服务验收锚资源侧读数——健康绿 ≠ backend 就位；验收三件 =
  健康 + 进程表含本件 + 一次真实生成。
- 规则：检查器自己要先证明能变红——每条判据带阳性对照（命中合成样本才算数，不许
  静默空结果），输入全集非空（取不到即报错，不悄悄变小）；把页面文字、日志行数这类
  东西当指标读之前，先用已知开、已知关的两侧样本验过它跟着被测对象变，验不了的那面
  如实写"未实测"。报告里常驻的非零读数当场定性：查明并修检查器，或写成具名豁免。
- 规则：遍历工作树的检查器只遍历 git 索引里的文件，或先清被忽略的缓存目录
  （`__pycache__/`、`build/`）；无法解码的被跟踪文件交给专门的检查项判红。
- 规则：检查要接到门上——脚本里每一行检查要么失败即中止，要么明写"仅记录、不拦截"。
